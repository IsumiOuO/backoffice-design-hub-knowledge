# 後台功能簡易規格

這裡是給規劃、前端、後端、QA 與其他查詢者使用的入口。

每份文件只回答五件事：

1. 這個功能做什麼。
2. 對應哪個 Figma 畫面。
3. 使用者會經過哪些步驟。
4. 各單位目前可以依據哪些資訊工作。
5. 還有哪些規則沒有確認。

不需要閱讀 AI 狀態、Claim ID、Component Key、JSON 或驗證流程。

## 功能列表

| 功能 | 目前可查詢 | 仍待補充 |
|---|---|---|
| [新增事件主類別](create-event-main-category.md) | 四步驟流程、畫面用途、裝置版型 | 權限、驗證、圖片規則、送出結果 |
| [編輯事件主類別](edit-event-main-category.md) | 四步驟流程、圖片列表／上傳狀態 | 權限、資料保存、圖片規則、送出結果 |
| [單一事件參數更新](single-parameter-update.md) | 編輯與確認兩步驟流程 | 投分參數定義、驗證、權限、送出結果 |

## 怎麼查

- 想了解用途：看「功能說明」。
- 想找設計稿：看「畫面與簡單說明」，圖片可直接點進 Figma。
- 想了解操作：看「操作流程」。
- 想知道能不能開發或測試：看「各單位可以先使用的資訊」。
- 找不到答案：看「待確認」，不要自行推測。

## 圖文查詢試測

目前可用「新增事件主類別」測試圖文查詢。結果會包含簡短答案、對應截圖、Figma 連結與規格來源；遇到未定規則時會明確標示待確認，不會自行補答案。

```bash
node scripts/query-specs.mjs "新增事件主類別 Step 2 做什麼"
node scripts/query-specs.mjs "新增事件主類別圖片有什麼限制" --json
```

這是 Telegram Bot 串接前的本地試測；之後 Bot 可以直接使用相同的圖檔與查詢索引。

## 怎麼維護

一般維護者只需要修改這個 `specs/` 目錄中的白話說明。

- 說明不正確：直接修改文字。
- 規則已確認：從「待確認」移到「已知規則」。
- 有新畫面：增加 Figma 連結與簡短用途。
- 不確定：保留在「待確認」，不要猜答案。

AI 與維護工具會負責同步內部索引、詳細資料與驗證結果。

## 文件狀態

- **可供查詢**：可以依文件內容回答，但可能仍有待確認事項。
- **待補充**：只有畫面線索，尚不足以說明完整功能。
- **已停用**：不應再作為現行功能依據。

目前三份文件皆為「可供查詢」。
